# 还没做的三维

已经接上的透视、镜头、网格、景深和默认光以 [SPEC.md](../../SPEC.md)「实体和镜头」为准。`<model object>` 把 three.js 的几何体放进这台场景。还没有的是点选和作者灯光。

## 点选

点选不画 PNG。它和 `check` 一样读 `.layer`、做布局、建矩阵，然后回答「这个像素打中谁」。绘制和点选共用同一套投影和同一套压平规则，避免出现「画面上是 A、点中的是 B」。

```ts
pickLayer(source, { x, y }, options?) => {
  hit: { path, id, tag, localX, localY, depth } | null
}
```

`x`、`y` 是根画布上的像素，y 向下。`options` 与 `renderLayer` 共用 `baseDir` 等读文件的字段，不共用 `scale`：点的坐标永远是未缩放的画布像素。

命中区域是布局盒子（文字含 padding 和 border，形状是形状的盒子，线条是线宽展开后的盒子），不是字形墨迹。字距中间的空隙也算点中该文字。`ink` 继续只给越界检查和调试用。

算法：

1. 用和绘制相同的矩阵链，找出所有包含该屏幕点的候选。屏幕点先乘祖先的二维矩阵；遇到开了镜头的 layer 之后改成射线：射线从观众位置出发，穿过该点。
2. 把射线乘到元素局部坐标系（父矩阵的逆），与局部平面 `z = 0` 求交。交点的 `(localX, localY)` 落在布局盒子内才算命中。矩阵不可逆时，这棵子树没有命中。
3. 压平过的子树不再用子元素自己的 `z` 和外面的平面比深度。射线先与压平后的那一张平面相交，命中之后在这张平面的二维结果里按绘制顺序取最上面的子元素。
4. 同一台镜头下有多个命中时，取 `depth` 最小且为正的一个（离观众最近）。`depth` 是交点到观众的距离，单位像素。距离差小于 0.5px 视为相同，然后取绘制顺序上更靠上的那个。
5. 背面命中有效。不因为法线朝后就丢掉。
6. 观众背后的元素、`opacity` 小于 0.01 的元素、被 `overflow="hidden"` 裁掉的部分，不参与。
7. 都没有命中时 `hit` 为 `null`。这不是错误。

`path` 与报告里的 `path` 相同。`localX`、`localY` 是布局盒子局部坐标，左上角为原点，给 `<canvas>` 或后续编辑定位用。

命令行与 `check` 并列，不出图：

```bash
npx tsx src/cli.ts pick examples/card.layer --at 540,700
```

标准输出是一行 JSON：`{ "hit": { "path": "…", "localX": 12, "localY": 8, "depth": 860 } }` 或 `{ "hit": null }`。源文件有 **error** 级问题时退出码为 1，和 `check` 相同。仅仅没有点中，退出码为 0。

调试绘制（`render --debug`）已经会沿 `quad` 的四边描一圈。点选本身不往调试图上打点；要核对某一点时，运行 `pick` 再对照 `path`。

实体（`sphere`、`torus`、`tube`、`model`，以及写了 `depth` 的形状）的点选还没定。平面点选先按布局盒子，不按墨迹多边形。

## 作者灯光

内置主光和固定工作室环境已经在画，见 SPEC「实体和镜头」的 `material`。作者指定的灯光、作者环境贴图还没有。属性 `shadow` 仍是平面上的偏移暗边，不跟三维光源。模型只把金属度和粗糙度映射到现有的 `metal` / `plastic`，不读 three.js 的灯光。

## three.js 的几何体

`Scene3D` 这个名字留着，不要挪作他用。它不是一块位图视口。

把 three.js 画成一张图再贴到平面上，内部深度出不了这块视口：网格盖不住外面的文字，线稿和标注也用不到模型身上的深度。Flex Layer 只拿几何体，放进自己的场景里光栅。遮挡、描线、锚定标注和多帧都走现有的深度缓冲。

tsx 里不增加标签。`<model src="hero.glb">` 的内存版是 `object`：

```tsx
import { canvas } from 'flexlayer'
import * as THREE from 'three'

const shape = new THREE.Shape().moveTo(0, 0).lineTo(80, 0).lineTo(40, 60).closePath()
const part = new THREE.Mesh(
  new THREE.ExtrudeGeometry(shape, { depth: 20 }),
  new THREE.MeshStandardMaterial({ color: '#7dce8a', metalness: 0.3 }),
)

export default canvas.create(
  <layer width={800} height={600} camera="fov 30, orbit 30 20">
    <model object={part} unit={1} stroke="#1c1915" hidden="#9a8f80" />
  </layer>,
)
```

`three` 是可选的 peer dependency。`fromThree` 在 `flexlayer/three`，核心不 import `three`。`.layer` 写不了内存对象，仍用 `src`。

读这些：几何体、世界矩阵、顶点色以外的材质颜色、`MeshStandardMaterial` 的 `metalness` 和 `roughness`、`DoubleSide`。金属度不小于 0.5 映射到 `metal`，否则 `plastic`。节点上的 `material` 覆盖整只模型。

不读这些：着色器、灯光、后处理、贴图、顶点色、骨骼。`SkinnedMesh` 只用绑定姿态。`Line` 和 `Points` 跳过。`InstancedMesh` 按实例矩阵展开。类型用 `isMesh`，不用 `instanceof`。

坐标只在投影时换一次。three.js 和 glb 都是 y 向上；作者空间 y 向下写在 `transformPoint` 里。负的线性行列式会把绕序翻过来，适配器把三角形换回正面。

不写 `unit` 时，每只 `<model>` 按 contain 缩放并居中塞进外包 layer。装配体要拆成多只 `<model>` 时写同一个 `unit`，原点落在这一层的 origin（默认中心），部件之间的世界坐标还在。

每一帧可以改 Object3D 再交给 `<model>`。缓存按几何内容的哈希，不按文件修改时间。

能用 three.js 造形状：几何体、数学库、场景树、`ExtrudeGeometry`、布尔库、程序网格，以及从 `readFileSync` 读进来再 `parse()` 的加载器。`WebGLRenderer`、着色器、灯光、后处理、`OrbitControls` 不参与出图。按网址加载的加载器多半要 DOM 或 `fetch`，不在这条路径里。

浏览器里的 R3F 组件先不做。那要把光栅器从 `@napi-rs/canvas` 和 `node:fs` 上解开。
