# 3D 方案选择与点选

已经接上的部分以 [SPEC.md 第 3 章](../../SPEC.md) 为准：

- `perspective` 写在父 `layer` 上，单位像素，灭点是这一层盒子的中心。
- `rotateX`、`rotateY`、`z` 写在要转动或推近的子元素上，不改变布局。`z` 正方向朝观众。
- 直接子元素先按中心深度排序，近的后画。再往里的子孙画进那一张平面。
- 带三维姿态的平面按 4 倍分辨率绘制，再平均缩回，斜边有抗锯齿。没有三维姿态的内容仍是原来的二维绘制。
- 没有祖先 `perspective` 时仍按二维绘制，并报 `flatten-3d`。`z` 大于等于视距时报 `behind-camera`，该元素不绘制。
- `sphere`、`box`、`extrude`、`model` 进入父 `layer` 的同一台 `perspective`。没有网格的层仍走平面透视。`model` 的 `src` 是一个 `.glb`。作者不写灯光；渲染器自带默认光。网格用自带的三角形光栅绘制。`Scene3D` 仍不使用。

还没有：`pickLayer`、作者灯光、`Scene3D` 视口。内置主光会在同一台透视场景的不透明网格和平面上投下硬边影子。没有自己 `perspective` 的嵌套层也算这台场景。报告里的 `quad`、投影后的 `ink`，以及调试框上的投影四边已经接上。下文从「点选」起是这些还没做的部分，和已经接上的绘制不一致时，以 SPEC 为准。

平面透视不另起标签：`rotateX`、`rotateY`、`z`、`perspective` 和现在的 `rotate`、`scale` 同类。点选是这个空间上的纯函数：从画布上的一个像素逆投影到平面，重叠时取得最近的那张。网格是另外四个标签，见 SPEC，不占用 `Scene3D`。

要写的名字：`rotateX`、`rotateY`、`z`、`perspective`。都是属性。绕画面法线的旋转继续叫 `rotate`。沿平面法线的位移就叫 `z`，单位是像素。不要另起 `camera`、`rotateZ`、`translateZ`、`z-index`，也不要把这些收成一条 `transform: rotateX() …` 函数串。

[SPEC.md 第 14 章](../../SPEC.md) 里同时预留了 `Scene3D`。这个名字不拿来做 2.5D 的上下文。若以后要放 Three.js，它是一块视口平面，见「以后的 Scene3D」。现在不实现。

## 决定

参数写在 `Layer` 上，不增加 `Scene3D`。

若干兄弟平面共用一个视距和一个灭点时，CSS 把这件事写成父元素上的 `perspective`，不为此发明新标签。Flex Layer 也一样：结构标签只有 `Layer`，定位、分组、整棵子树的旋转已经都写在 `Layer` 上。若用 `Scene3D` 来表示这个视距，就要把 `x`、`y`、宽高、谁能写 `background` 再讲一遍，而行为和「写了 `perspective` 的 Layer」相同。`Scene3D` 留下给另一种内容：Three.js 画出来的视口。两种内容在父级看来都是平面，合成规则只有一套，见「以后的 Scene3D」。

因此：

1. **`rotateX`、`rotateY`、`z`** 写在要转动或推近的那一层上，归属和 `rotate`、`scale` 相同。
2. **`perspective`** 写在父 `Layer` 上，是直接子元素共用的视距。这一层就是三维上下文。整张画布要透视时，写在根 `Layer` 上即可，根上的 `background` 保持原样。
3. **布局**继续用现在的 Yoga。这四个属性和 `rotate`、`scale` 一样，只影响绘制和点选，不改 `box`。
4. **点选**用 Flutter `RenderTransform.hitTest` 的逆变换：把屏幕点变回元素局部坐标，再判断在不在布局盒子里。同一个 `perspective` 下多张平面都命中时，用 Three.js `Raycaster` 的规则，按到观众的距离取最近。
5. **绘制**留在现有的二维 Canvas 上。子树先画进离屏，再把四边形贴回画布。不换 WebGL，不引进网格。

单张卡片也是两层 `Layer`：外层放位置和 `perspective`，内层放 `rotateY` 和 `z`。外层这种包法海报里本来就有，用来定位。`perspective` 不作用于写下它的那一层自己，只作用于子元素。这样兄弟之间的灭点只有一个，不会出现「每张卡片自带一台相机」。

## 对照了哪几套写法

成熟框架把「元素是什么」「变换改不改布局」「点的是哪一个」分成三件独立的事来写。下表只保留和 Flex Layer 有关的那几条。

| | 元素是什么 | 变换与布局 | 点选怎么写 | 我们借的 | 不借的 |
| --- | --- | --- | --- | --- | --- |
| CSS Transforms 2 | 盒子仍是平面。父级的 `perspective` 让子元素共用一台视点；默认先压成一张图 | `transform` 不改布局 | 用变换后的 border box。实现上把点逆变换回局部坐标 | 平面、压平、透视写在父级、`z` 正方向朝观众。不为此新增标签 | `transform: rotateX()` 这种函数串。本仓库一种变化一个属性 |
| After Effects / Motion | 3D 图层是一块带锚点的平面，开关在图层上，相机在合成上 | 位置、旋转不回流到排版 | 在合成视图里点平面。选择和渲染分开 | 平面 + 一个透视距离就够用 | 独立相机对象、灯光、材质 |
| Three.js | `Object3D` 组成场景图，叶子可以是网格。`CSS3DRenderer` 则把 DOM 平面放进这棵场景图 | 矩阵不参与排版 | `Raycaster` 的结果按 `distance` 排序。嵌在页面里时，先点中那块画布，再用局部坐标打射线 | 平面之间按距离排序。以后的视口也是先点中平面，再在内部打射线 | 把整张海报换成场景图。网格只活在视口里面 |
| Flutter `Transform` | 子组件先按二维布局，再乘变换 | 变换不影响布局约束 | `hitTest` 把指针位置乘逆矩阵 | 逆变换进局部盒子；和现有「`box` 是变换前、`ink` 是变换后」同一条 | 把 `Matrix4` 交给作者去写 |

不整个引进其中任何一套。三维没有第二份盒子树，就是在现有 `LayoutNode` 上多四个数。

## 坐标

和现在一样，**y 轴向下**，数字是像素。写了 `perspective` 的 `Layer`，原点在它盒子的左上角。

`z` 的正方向**朝观众**。观众到 `z = 0` 的距离就是父级的 `perspective`（像素）。这和 CSS 的 `perspective` 矩阵一致：局部点 `(x, y, z)` 在透视除法之后是

```text
w = 1 - z / perspective
x' = vx + (x - vx) / w
y' = vy + (y - vy) / w
```

`(vx, vy)` 是灭点，默认是这个父 Layer 盒子的中心。`z` 越大，平面越大。`z` 接近 `perspective` 时会放到无限远；`z >= perspective` 的平面中心在观众上或观众后，不绘制、不参与点选，报 `behind-camera`。

旋转绕 `origin`（已有属性，默认 `center`），单位度。作用在局部点上的顺序，接在今天 `src/matrix.ts` 的 `aroundPivot` 后面：

1. 把 `origin` 平移到局部原点
2. `scale`（仍是一个数，不增加 `scaleX`）
3. `z`
4. `rotateX`，再 `rotateY`，再 `rotate`（绕法线，顺时针为正，和现在相同）
5. 平移回去

先缩放、再绕轴，这样现有只写 `rotate` / `scale` 的文件，矩阵的二维部分和今天一致。`rotateX`、`rotateY`、`z` 都缺省为 0。没写 `perspective` 的 Layer 和现在完全一样。

`src/matrix.ts` 里的 `Matrix` 是二维仿射，绘制和 `src/report.ts` 的 `nodeMatrix` 都用它。三维用另一套 4×4，只在节点写了 `rotateX`、`rotateY`、`z`，或祖先 Layer 写了 `perspective` 时启用。

## 布局

Yoga 在元素自己的平面里算，单位仍是像素。`rotateX` 不会把 flex 的 `gap` 变成近大远小；近大远小只出现在投影之后。

报告里的分工保持第 10 章的句子，只把「旋转、缩放」扩成「旋转、缩放和透视」：

- `box`：变换前的布局盒子，只累加平移。
- `ink`：投影之后的轴对齐外接矩形，并和祖先的 `overflow="hidden"` 求过交集。`overflow-canvas` 继续看 `ink`。
- 另加 `quad`：投影后的四个角，画布坐标，顺序为左上、右上、右下、左下。点选和调试用它，不用外接矩形去猜斜着的卡片。

## 上下文和压平

写了 `perspective` 的 `Layer` 建立一个三维上下文。它的直接子元素（`Layer`、`use`、图形）共享这一次透视和这一次深度排序。再往里的孙子默认先画进各自的父 Layer，变成那一张平面上的像素，不拿自己的 `z` 去和外层的卡片交错。

要让两张卡片互相遮挡、各自带 `z`，就把它们写成这个 `perspective` Layer 的直接子层。不要在中间再包一层没有 `perspective` 的 Layer，那一层会先把两张卡片合成一张图。

下面这些已经会把子树合成一张图。合成结果仍可以作为父级上下文里的**一张**平面（这张平面自己可以有 `z` 和 `rotateY`），但平面内部不再和外面交错：

| 已有写法 | 为什么压平 |
| --- | --- |
| `opacity` 小于 1 | 先乘透明度再贴，和 CSS 一样必须先得到一张图 |
| `blur`、`filter`、`grade`、`grade-mask`、`glass`、`backdrop-blur`、`blend`、`noise`、`overlay` | 这些效果的输入就是该节点已绘制像素 |
| `overflow="hidden"` | 裁剪发生在这一层的盒子上，裁完已是二维 |

带这些写法的如果是 `perspective` 那一层自己：子元素先在这一层内部按深度排好，再合成一张图，最后才和这一层的兄弟一起画。内部的远近出不了这一层。

嵌套时，内层 `perspective` 先得到一张投影完的图，再作为外层的一张平面。两层的平面不放进同一次深度排序。

父链上没有任何 `perspective` 时，`rotateX`、`rotateY`、`z` 都不投影，仍按二维绘制，并报 `flatten-3d`（`warn`）。`hint` 写明在父 `layer` 上加 `perspective`。

## 绘制

`@napi-rs/canvas` 的 `setTransform` 只有二维仿射，和现在 `paint.ts` 的用法一致。透视除法不能写成一次 `setTransform`。

做法和滤镜同一条路：把这一层（含已压平的子树）画进离屏，得到一张位图，再贴到投影后的四边形上。

四边形不要只做一次仿射，也不要把平面切成互相重叠的三角形。一次仿射贴不准透视，重叠的三角形会让半透明的阴影和发光在接缝上叠两次。平面透视是一次单应：按四个角求出投影，每个输出像素只采样一次。整张平面先按 4 倍分辨率绘制，再平均缩回逻辑像素，用来抗锯齿。某个角落到观众身后、单应不稳定时，才退回不重叠的小块仿射。二维绘制不经过这一步。

两张平面在空间里相交时**不切分**。按平面中心在视空间里的深度排序，离观众近的后画。深度相同则保持现在的规则：后写的元素画在上面。这一点和浏览器、After Effects 的默认合成一样，要写进规范，避免实现时去做三角形互切。

背面照常绘制。不增加 `backface-visibility`。点选也打得到背面，见下一节。

`z >= perspective`、或投影后 `w <= 0` 的元素跳过绘制。

## 点选

点选不画 PNG。它和 `check` 一样读 `.layer`、做布局、建矩阵，然后回答「这个像素打中谁」。绘制和点选共用同一套 4×4 和同一套压平规则，避免出现「画面上是 A、点中的是 B」。

```ts
pickLayer(source, { x, y }, options?) => {
  hit: { path, id, tag, localX, localY, depth } | null
}
```

`x`、`y` 是根画布上的像素，y 向下。`options` 与 `renderLayer` 共用 `baseDir` 等读文件的字段，不共用 `scale`：点的坐标永远是未缩放的画布像素。

命中区域是**布局盒子**（文字含 padding 和 border，形状是形状的盒子，线条是线宽展开后的盒子），不是字形墨迹。字距中间的空隙也算点中该文字。这和 CSS 的 border box、Figma 点中文本层的方式一致。`ink` 继续只给越界检查和调试用。

算法：

1. 用和绘制相同的矩阵链，找出所有包含该屏幕点的候选。屏幕点先乘祖先的二维矩阵；遇到写了 `perspective` 的 Layer 之后改成射线：射线从观众位置 `(vx, vy, perspective)` 出发，穿过该点。
2. 把射线乘到元素局部坐标系（父矩阵的逆），与局部平面 `z = 0` 求交。交点的 `(localX, localY)` 落在布局盒子内才算命中。矩阵不可逆时，这棵子树没有命中。
3. 压平过的子树不再用子元素自己的 `z` 和外面的平面比深度。射线先与压平后的那一张平面相交，命中之后在这张平面的二维结果里按绘制顺序取最上面的子元素。
4. 同一个 `perspective` 下有多个命中时，取 `depth` 最小且为正的一个（离观众最近）。`depth` 是交点到观众的距离，单位像素。距离差小于 0.5px 视为相同，然后取绘制顺序上更靠上的那个。
5. 背面命中有效。不因为法线朝后就丢掉。
6. 观众背后的元素、`opacity` 小于 0.01 的元素、被 `overflow="hidden"` 裁掉的部分，不参与。
7. 都没有命中时 `hit` 为 `null`。这不是错误。

`path` 与报告里的 `path` 相同。`localX`、`localY` 是布局盒子局部坐标，左上角为原点，给 `<draw>` 或后续编辑定位用。

命令行与 `check` 并列，不出图：

```bash
npx tsx src/cli.ts pick examples/card.layer --at 540,700
```

标准输出是一行 JSON：`{ "hit": { "path": "…", "localX": 12, "localY": 8, "depth": 860 } }` 或 `{ "hit": null }`。源文件有 **error** 级问题时退出码为 1，和 `check` 相同。仅仅没有点中，退出码为 0。

调试绘制（`render --debug`）在已有的盒子和着墨框之外，用 `quad` 的四边再描一圈。点选本身不往调试图上打点；要核对某一点时，运行 `pick` 再对照 `path`。

## 在 `.layer` 里怎么写

`rotateX`、`rotateY`、`z`、`perspective` 的归属和今天的 `rotate` 相同：`Layer`、`use` 和图形写属性；文字若要写，放在 `style` 里，但作用到整段文字时仍应外包一层 `Layer`。`perspective` 写在图形或文字上没有子平面可看，报 `invalid-attr`，`hint` 说明挪到父 `Layer`。

```html
<layer width="1080" height="1920" background="#0f1115">
  <layer width="1080" height="800" x="0" y="560" perspective="900">
    <layer width="640" height="360" x="220" y="220" z="80" rotateY="-18" origin="center">
      <img src="cover.png" style="width:640px; height:360px" />
    </layer>
    <layer width="640" height="360" x="220" y="220" z="-40" rotateY="12">
      <div style="display:flex; flex-direction:column; gap:16px">
        <h1 style="font-size:72px">封面之后</h1>
        <p style="font-size:28px">这一层更远</p>
      </div>
    </layer>
  </layer>
</layer>
```

外层 `Layer` 只提供盒子和视距。两张卡片是它的直接子级，近的那张（`z="80"`）盖住远的。若在中间再包一层带 `opacity` 或 `blur` 的 `Layer`，两张会先合成，再一起倾斜，不能互相穿插。

线条仍然不能放进 flex。要斜着放一组线，包一层 `Layer`，把 `rotateX` 写在这层上，`perspective` 写在更外一层。

## 问题码

都挂在现有级别上，不新增级别。

| code | 级别 | 何时 |
| --- | --- | --- |
| `unknown-tag` | warn | 这一步的 `<Scene3D>` 仍不认识，写了就丢掉。以后它若作为 Three.js 视口实现，再从这张表删掉 |
| `invalid-attr` | warn | `perspective` 写在没有子平面的图形或文字上；`rotateX` 等写在了不允许的位置 |

## 以后的 Scene3D

现在不做。这里把边界写死，是为了让以后放进 Three.js 时不必改 `perspective` 和点选的含义。

统一的办法是外面只有一种东西：**一块平面加一张位图**。`Layer` 的位图由 flex、文字和图形画出来。`Scene3D` 的位图由 Three.js 画出来。父级不关心像素从哪来，只做同一件事：按 `rotateX`、`rotateY`、`z` 和父级的 `perspective` 把这块位图贴到四边形上，点选时用同一套逆投影。

这是页面里嵌一块三维视口的写法，和 `<model-viewer>`、Remotion 的 `ThreeCanvas`、After Effects 里先渲染再当图层用的三维对象一样。不是 Three.js `CSS3DRenderer` 那种把整棵海报收进场景图的写法。后者要换掉 Yoga，让网格的深度和标题互相穿插。那是另一个渲染器。

| | 父级看到的 | 自己内部 |
| --- | --- | --- |
| `Layer` | 一张平面。`z`、`rotateX`、`rotateY` 相对父级的 `perspective` | flex、文字、图形。没有第二台相机 |
| `Scene3D` | 同样是一张平面，属性与 `Layer` 相同，所以能被父级的 `perspective` 转成一张斜卡片 | Three.js 的相机、网格、灯光。内部深度出不了这块视口 |

因此有三条不能破：

1. **两台相机不合并。** 父级的 `perspective` 只投射这块视口的四边形。Three.js 的焦距、机位写在 `Scene3D` 里面，用它自己的名字（`fov`、相机位置），不要也叫 `perspective`。两套都叫透视时，同一张卡片会被投影两次。
2. **深度不交错。** 网格再靠前，也盖不住视口外面的兄弟 `Layer`；兄弟 `Layer` 也刺不进网格里。要让一个模型穿过标题，标题就得画进这个 `Scene3D`（贴成纹理，或作为视口内的平面），而不是做它的兄弟。这和现在「模糊、透明度会把子树收成一张图」是同一条。
3. **点选分两步，坐标只有一种。** `pickLayer` 先按平面规则返回 `Scene3D` 的 `path`、`localX`、`localY` 和这张平面的 `depth`。视口实现之后，可以用这对局部坐标换成 Three.js 的 NDC，再跑 `Raycaster`，把命中的对象放进同一个结果的 `object` 字段。只认识平面的调用方忽略 `object`。不要为网格另做一套屏幕坐标。

子节点也不混用。`Scene3D` 里面不是 flex，不能放 `h1` 或 `Rect`。内容是一次渲染回调，或一棵不进 Yoga 的外来子树。位图尺寸等于它的布局盒子乘 `scale`，然后走和倾斜 `Layer` 相同的贴四边形路径。

现在这步要为这条边界留住的，只有已经写在上面的三件事：深度和点选都针对平面，不针对像素；倾斜的层都是先得位图再贴四边形；`quad` 与 `localX`、`localY` 是交接坐标。`Scene3D` 以后只替换「谁来产生这张位图」。

## 明确不做

这一步不做 `Scene3D`，也不把视距做成标签。视距保持为 `Layer` 的 `perspective`。

- 网格、灯光、材质、环境贴图、阴影贴图。投影仍用现有的 `shadow`，它在平面局部里，不跟三维光源。网格留给以后的 `Scene3D` 视口，不进这套属性。
- 独立相机、镜头光圈、景深。
- 把相交的两张平面切成碎片再拼接。
- 用墨迹多边形做点选。点选看布局盒子。
- 在 `.layer` 里写矩阵数字或 `matrix3d(...)`。
- 为了三维换成 WebGL。二维海报仍走现在的 Canvas。
