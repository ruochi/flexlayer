# 还没做的三维

已经接上的透视、镜头、网格、景深和默认光以 [SPEC.md 第 3 章](../../SPEC.md) 为准。下面三件还没有：点选、作者灯光、`Scene3D` 视口。

## 点选

点选不画 PNG。它和 `check` 一样读 `.layer`、做布局、建矩阵，然后回答「这个像素打中谁」。绘制和点选共用同一套投影和同一套压平规则，避免出现「画面上是 A、点中的是 B」。

```ts
pickLayer(source, { x, y }, options?) => {
  hit: { path, id, tag, localX, localY, depth } | null
}
```

`x`、`y` 是根画布上的像素，y 向下。`options` 与 `renderLayer` 共用 `baseDir` 等读文件的字段，不共用 `scale`：点的坐标永远是未缩放的画布像素。

命中区域是布局盒子（文字含 padding 和 border，形状是形状的盒子，线条是线宽展开后的盒子），不是字形墨迹。字距中间的空隙也算点中该文字。`ink` 继续只给越界检查和调试用。

算法：

1. 用和绘制相同的矩阵链，找出所有包含该屏幕点的候选。屏幕点先乘祖先的二维矩阵；遇到写了 `perspective` 的 layer 之后改成射线：射线从观众位置出发，穿过该点。
2. 把射线乘到元素局部坐标系（父矩阵的逆），与局部平面 `z = 0` 求交。交点的 `(localX, localY)` 落在布局盒子内才算命中。矩阵不可逆时，这棵子树没有命中。
3. 压平过的子树不再用子元素自己的 `z` 和外面的平面比深度。射线先与压平后的那一张平面相交，命中之后在这张平面的二维结果里按绘制顺序取最上面的子元素。
4. 同一个 `perspective` 下有多个命中时，取 `depth` 最小且为正的一个（离观众最近）。`depth` 是交点到观众的距离，单位像素。距离差小于 0.5px 视为相同，然后取绘制顺序上更靠上的那个。
5. 背面命中有效。不因为法线朝后就丢掉。
6. 观众背后的元素、`opacity` 小于 0.01 的元素、被 `overflow="hidden"` 裁掉的部分，不参与。
7. 都没有命中时 `hit` 为 `null`。这不是错误。

`path` 与报告里的 `path` 相同。`localX`、`localY` 是布局盒子局部坐标，左上角为原点，给 `<draw>` 或后续编辑定位用。

命令行与 `check` 并列，不出图：

```bash
npx tsx src/cli.ts pick examples/card.layer --at 540,700
```

标准输出是一行 JSON：`{ "hit": { "path": "…", "localX": 12, "localY": 8, "depth": 860 } }` 或 `{ "hit": null }`。源文件有 **error** 级问题时退出码为 1，和 `check` 相同。仅仅没有点中，退出码为 0。

调试绘制（`render --debug`）已经会沿 `quad` 的四边描一圈。点选本身不往调试图上打点；要核对某一点时，运行 `pick` 再对照 `path`。

网格（`sphere`、`box`、`cylinder`、`torus`、`tube`、`extrude`、`model`）的点选还没定。平面点选先按布局盒子，不按墨迹多边形。

## 作者灯光

内置主光和固定工作室环境已经在画，见 SPEC 第 3 章的 `material`。作者指定的灯光、作者环境贴图还没有。属性 `shadow` 仍是平面上的偏移暗边，不跟三维光源。完整的 PBR 材质留给下面的 `Scene3D` 视口。

## Scene3D 视口

现在不做。`Scene3D` 这个名字留着，不要挪作他用。边界写在这里，是为了以后放进 Three.js 时不必改 `perspective` 和点选的含义。

统一的办法是外面只有一种东西：一块平面加一张位图。`layer` 的位图由 flex、文字和图形画出来。`Scene3D` 的位图由 Three.js 画出来。父级不关心像素从哪来，只做同一件事：按 `rotateX`、`rotateY`、`z` 和父级的 `perspective` 把这块位图贴到四边形上，点选时用同一套逆投影。

这是页面里嵌一块三维视口的写法，不是把整棵海报收进场景图。后者要换掉 Yoga。

| | 父级看到的 | 自己内部 |
| --- | --- | --- |
| `layer` | 一张平面。`z`、`rotateX`、`rotateY` 相对父级的 `perspective` | flex、文字、图形。没有第二台相机 |
| `Scene3D` | 同样是一张平面，属性与 `layer` 相同 | Three.js 的相机、网格、灯光。内部深度出不了这块视口 |

三条不能破：

1. **两台相机不合并。** 父级的 `perspective` 只投射这块视口的四边形。Three.js 的焦距、机位写在 `Scene3D` 里面，用它自己的名字，不要也叫 `perspective`。
2. **深度不交错。** 网格再靠前，也盖不住视口外面的兄弟 `layer`。要让一个模型穿过标题，标题就得画进这个 `Scene3D`，而不是做它的兄弟。
3. **点选分两步，坐标只有一种。** `pickLayer` 先按平面规则返回 `Scene3D` 的 `path`、`localX`、`localY` 和这张平面的 `depth`。视口实现之后，再用这对局部坐标跑内部的射线，把命中的对象放进同一个结果的 `object` 字段。不要为网格另做一套屏幕坐标。

`Scene3D` 里面不是 flex，不能放 `h1` 或 `rect`。内容是一次渲染回调，或一棵不进 Yoga 的外来子树。
